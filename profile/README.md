## Project History

### 3차 — PICKLE (맛집 RAG 챗봇)

- **도메인**: 신대방삼거리 일대 식당 **100곳** · 메뉴 **2,008** · 리뷰 **422** (다이닝코드 크롤링)
- **핵심**: LangGraph 라우팅(`embedding` / `fixed`) → JSON Schema 슬롯 → SQLite(base64 임베딩) + 코사인 유사도 교집합 → **Grounded** 단일 식당 추천
- **UI**: Streamlit + Kakao Map · 검색/챗봇 모드 전환 · `session_id` 대화 히스토리
- **품질**: 골드셋 50케이스(`fixed` 20 + `embedding` 30) · `src_test3`/`run_qa` 회귀 — pass rate **82%**, target hit **96%**

### 4차 — LG Home (가전 AI 추천·상담 웹)

- **도메인**: TV·냉장고·세탁기·에어컨·청소기 5개 카테고리 (LG 공식몰 크롤링 · 제품코드 `TVT`/`REF`/`WMT`/`ACT`/`VAC`)
- **핵심**: LangGraph 분기(fall case · 후속 질문 · 제품군 분류 · intent 슬롯) → Django ORM 상품 검색 + **Pinecone 매뉴얼 RAG** · 찜 범위(`from_favorites`) 검색
- **UI**: 필터 검색 + **LG봇 LGneer** — Django SSR · Tailwind v4 · DaisyUI · 찜 · 마이페이지 · 대화 히스토리
- **문서**: `docs/` 파트별·기능별 위키(아키텍처 · API · DB · LangGraph · RAG · 프론트 QA 1·2차)
- **품질**: `common/llm_frame.ipynb` 노드별 평가 — fall case **92%** · 후속 질문·제품군 분류 **100%**

3차에서 **좁은 도메인·SQLite 임베딩·골드셋 회귀 평가**, 4차에서 **Streamlit → Django 풀스택·Pinecone RAG·Figma→SSR UI·파트별 docs 위키**까지 쌓았습니다. 3·4차 경험(도메인 RAG, LangGraph, 평가, 웹 서비스)을 바탕으로 **배포까지 염두에 두고** 파이널 주제·아키텍처를 찾는 중입니다.

## Team Identity

**「LLM 데모」가 아니라, 근거 있는 AI 서비스를 끝까지 만드는 팀**입니다.

- 요구사항 → 데이터 → RAG·에이전트 → 평가·가드레일 → 서비스 UX를 **한 흐름**으로 연결
- DB·문서에 없는 정보는 생성하지 않는 **Grounded** 설계 (3차 식당 DB, 4차 상품·매뉴얼)
- 골드셋·노드별 지표·리포트로 **재현 가능한 품질 관리**
- 3·4차에서 다진 역할 분담·문서화·PR 리뷰를 파이널에도 유지

## How We Work

**협업**

- Issue 기반 작업 분리 · Branch 전략 · Conventional Commits
- PR 리뷰 후 Merge
- 프롬프트·RAG·평가 결과 및 설계 근거를 `README` · `docs`에 문서화

**저장소 원칙**

- 프로젝트별 독립 repo + 조직 `.github` 프로필로 팀 정체성 유지
- `src` / `common` · `database` / `products/data` · `frontend` / `templates` · `src_test*`(3차 평가) 등 구조화된 폴더
- 데이터 · 문서 · `.env` 분리 · 프롬프트·평가·DB 스냅샷 버전 관리
- 산출물 · 실험 로그 · 골드셋 · 평가 리포트 기록
